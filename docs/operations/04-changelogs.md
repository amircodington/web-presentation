# 04 — The Two Changelogs

Two audiences who need completely different things, so two files. Merging them serves neither.

| | `CHANGELOG.md` | `CHANGELOG-USER.md` |
|---|---|---|
| Audience | Developers and agents | The Wealth Club team, booth operators |
| Language | English | **Persian** |
| Source | Generated from Conventional Commits | Hand-written at release time |
| Answers | "What changed in the code?" | "What will I notice on the screen?" |
| Contains | Scopes, commit hashes, breaking changes | Plain descriptions of visible behaviour |

## `CHANGELOG.md` — technical

[Keep a Changelog](https://keepachangelog.com) format, generated by `npm run release` from
commits since the last tag. **Never hand-edited** — an edit is lost on the next release.

```markdown
## [1.2.0] — 2026-09-14

### Added
- **engine:** dive transition for cross-canvas jumps (a3f9c21)
- **quiz:** age-band scoring for the 12–15 segment (7b2e004)

### Fixed
- **kiosk:** clear quiz answers on idle reset (c81a930)

### Performance
- **media:** pause video decode on non-active scenes (2f4d118)
```

`docs`, `chore`, `style` and `test` commits are excluded — they are in git history, and a
changelog that lists everything is a changelog nobody reads.

## `CHANGELOG-USER.md` — for people

Written by a human, in Persian, at every release. The release script pauses and opens an editor,
and refuses to continue if the entry is empty.

```markdown
## نسخه ۱.۲.۰ — ۲۴ شهریور ۱۴۰۵

### ✨ جدید
- آزمون مالی حالا برای نوجوانان ۱۲ تا ۱۵ سال پیشنهاد جداگانه می‌دهد.
- حرکت بین بخش‌ها نرم‌تر و سینمایی‌تر شد.

### 🛠 بهبود
- ویدیوها روان‌تر پخش می‌شوند و تصویر کندی ندارد.

### 🐞 رفع اشکال
- اگر کسی وسط آزمون صفحه را رها کند، پاسخ‌هایش برای نفر بعدی باقی نمی‌ماند.
```

The rules for writing it:

- **Describe what a person sees**, never a file, a function, or a component name.
- **Persian dates** (Jalali), matching everything else on screen.
- **No jargon** — no "refactor", no "IndexedDB", no commit hashes, no ticket numbers.
- **Omit anything invisible.** A dependency bump does not belong here. If nobody would notice
  it, it is not a user-facing change, and padding the list trains people to stop reading it.
- Three sections only: `✨ جدید` / `🛠 بهبود` / `🐞 رفع اشکال`. Drop any that are empty.

The test for a good entry: could the person running the booth read it aloud to a colleague and
have them understand what is different? If not, rewrite it.

## Why the pause is deliberate

It would be easy to generate the Persian changelog by stripping prefixes off commit subjects.
That produces text that is technically accurate and useless — "add dive transition for
cross-canvas jumps" tells a booth operator nothing. Thirty seconds of human writing per release
is the cost of the file being worth having at all.
